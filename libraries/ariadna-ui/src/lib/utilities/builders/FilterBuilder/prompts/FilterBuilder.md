# Техническое задание

Необходимо полностью реализовать утилитарную функцию FilterBuilder по требованиям ниже, включая ВСЕ перечисленные
в структуре файлы.

## Структура:

```text
├── FilterBuilder                                     # Каталог с именем утилиты
│   ├── tests                                         # Каталог с Unit-тестами
│   │   ├── FilterBuilder                             # Каталог с Unit-тестами для утилиты
│   │   │   ├── FilterBuilder.test.ts                 # Unit-тесты главной утилиты
│   ├── types                                         # Каталог с типами директивы
│   │   ├── FilterBuilder.enum.ts                     # Enum утилиты
│   │   ├── FilterBuilder.types.ts                    # Типы утилиты
│   ├── FilterBuilder.ts                              # Основной (входной) файл элемента
│   ├── FilterBuilder.d.ts                            # Основной файл с типами элемента
```

## Утилита FilterBuilder
Техническое задание для утилиты QueryBuilder:

1. Назначение
   * Утилита `FilterBuilder` предназначена для построения сложных фильтров над массивами объектов (сущностей) с помощью
   цепочного Fluent API. Она позволяет динамически выбирать поля (в том числе вложенные), комбинировать их с помощью
   логических операторов (`AND`/`OR`), а также применять пользовательские условия фильтрации к выбранным полям. 
   Утилита облегчает создание гибких и читаемых фильтров для обработки данных в приложениях.
2. Общие требования:
   * Утилита должна поддерживать SSR.
   * Утилита должна быть независимой и не иметь внешних побочных эффектов.
   * Интерфейс должен быть реализован в виде класса с поддержкой цепочки вызовов (Fluent API).
3. Функциональные требования
   * Возможность выбора одного или нескольких полей для фильтрации, включая вложенные поля произвольной глубины.
   * Поддержка логических операторов AND и OR для объединения условий фильтрации.
   * Возможность конфигурирования набора полей и логических операторов.
   * Метод для пошагового выбора полей, поддерживающий вложенность.
   * Методы для добавления логических операторов между условиями.
   * Метод для применения пользовательской функции фильтрации к выбранным полям и возврата отфильтрованного массива
   сущностей.
   * Корректная обработка ошибок: выбрасывание исключений при некорректной конфигурации (например, несоответствие 
   количества полей и операторов, отсутствие выбранных полей и др.).
   * Поддержка работы с пустыми массивами данных и корректное поведение при отсутствии совпадений.
   * Возможность фильтрации как одномерных, так и многомерных (вложенных) массивов сущностей.
   * Все публичные методы должны возвращать экземпляр FilterBuilder для поддержки цепочки вызовов (Fluent API).
