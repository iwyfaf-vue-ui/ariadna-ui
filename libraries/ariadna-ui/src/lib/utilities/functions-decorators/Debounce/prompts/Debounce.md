# Техническое задание

Необходимо полностью реализовать утилитарную функцию-декоратор Debounce по требованиям ниже, включая ВСЕ перечисленные
в структуре файлы.

## Структура:

```text
├── Debounce                                          # Каталог с именем утилиты
│   ├── tests                                         # Каталог с Unit-тестами
│   │   ├── Debounce                                  # Каталог с Unit-тестами для утилиты
│   │   │   ├── Debounce.test.ts                      # Unit-тесты главной утилиты
│   ├── types                                         # Каталог с типами директивы
│   │   ├── Debounce.enum.ts                          # Enum утилиты
│   │   ├── Debounce.types.ts                         # Типы утилиты
│   ├── Debounce.ts                                   # Основной (входной) файл элемента
│   ├── Debounce.d.ts                                 # Основной файл с типами элемента
```

## Утилита Debounce
Техническое задание для утилиты Debounce:

1. Назначение
   * Утилита `debounce` предназначена для оптимизации частых вызовов функций (например, обработчиков событий `input`, 
   `scroll`, `resize`). Она гарантирует, что функция будет вызвана только после того, как с момента последнего вызова
   прошло определённое время (задержка).
2. Общие требования:
   * Утилита должна поддерживать SSR.
   * Код должен быть модульным и легко интегрируемым в существующую кодовую базу.
   * Утилита должна быть совместима с современными браузерами и поддерживать основные среды выполнения JavaScript.
   * Минимизировать нагрузку на браузер.
3. Функциональные требования
   1. Параметры функции:
      * `callback`: Функция, вызов которой необходимо "дебаунсить". Обязательный параметр.
      * `timeout`: Задержка в миллисекундах  По умолчанию 300 мс.
      * `immediate`: Если значение `true`, то `callback` функция вызывается немедленно. В противном случае она 
      вызывается на завершающем этапе. По умолчанию `false`.
   2. Поведение:
      * При частых вызовах функция выполняется только один раз после окончания задержки.
4. Требования к тестированию:
   * Покрыть директиву unit-тестами:
5. Требования к документации:
   * Типы должны находится в отдельном файле `Debounce.d.ts`;
   * Описание сценариев применения утилиты.
