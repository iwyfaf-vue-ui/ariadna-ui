## Unit-тест для Composable

Выполняй эти инструкции при команде - `Напиши тесты для composable X`.

Предварительно посмотри как в проекте описаны другие подобные тесты.

Я хочу, чтобы ты выступил в качестве Typescript и Vue 3 Senior разработчика. Как только я предоставлю код, твоя задача
разработать полный набор Unit-тестов для предоставленной кодовой базы. Следуй этим рекомендациям для эффективного
процесса тестирования:

1. Разберись в кодовой базе: проанализируй код TypeScript тщательно, шаг за шагом. Выяви возможную двусмысленность или
   недостающую информацию, такую как константы, определения типов, условия, внешние API и т.д., и укажи шаги, а также
   вопросы и попроси разъяснений для лучшего понимания кода. Переходи к следующему шагу только после того, как ты
   полностью проанализируешь кодовую базу.
2. Фреймворк тестирования: Для решения этой задачи используй фреймворки тестирования Vitest версии 3.1.1, happy-dom
   версии 17.0.0 и @vue/test-utils версии 2.4.6.
3. Разрабатывай небольшие, сфокусированные тесты: Каждый модульный тест должен быть сосредоточен на одной
   функциональности, что повышает удобство чтения и простоту отладки. Убедись, что каждый тест изолирован и не зависит
   от других. Смоделируй поведение внешних зависимостей, используя фиктивные объекты, чтобы повысить надежность и
   скорость твои тестов.
4. Структурируй и называй свои тесты правильно: Твои тесты должны иметь четкую структуру и использовать описательные
   названия, чтобы было понятно их назначение.
5. Следуй приведенной ниже структуре теста. Внимательно изучи комментарии и следуй им при написании тестов. Обрати
   особое внимание на `<METHOD_NAME>`, этот `describe` обязателен в структуре тестов. В нем ты должен разместить тесты
   определенной функциональной области тестируемого модуля. Это поможет разбить тесты на группы.
6. Тестировать нужно с монтированием composable как в примере ниже, с применением функции `mountWithComposable()`:
7. Там где присутствует реальная реализация - не мокируй.

```
function mountWithComposable(props: SomeProps, slots: any = {}, route = { path: '/' }) { 
 const emits = vi.fn();
 
 return mount(
   defineComponent({
     setup() {
       const result = useComposable(props, slots, emits);
       return { ...result, emits };
     },
     render() {
       return h('div');
     },
   }),
   {
     global: {
       config: {
         globalProperties: {
           $route: route,
         },
       },
     },
   },
 );
}

describe('<NAME_OF_MODULE_TO_TEST>', () => {
// Определи тестовые переменные верхнего уровня здесь

beforeAll(async () => {
// Логика одноразовой инициализации _если требуется_
});

beforeEach(async () => {
// Логика, которая должна запускаться перед каждым тестом, _если требуется_
});

afterAll(async () => {
// Логика, которая должна быть запущена после всех тестов, _если требуется_
});

// Наличие <METHOD_NAME> обязательно в структуре тестов. Вместо <METHOD_NAME> ты должен указать тестируемую область.
describe('<METHOD_NAME>', () => {
// Определи здесь переменную уровня метода

    // Используй method-lavel beforeAll, beforeEach or afterAll _если требуется_

    // Тестовый пример должен начинаться с "Should" (обязательно с заглавной буквы) и заканчиваться точкой (".")
    it('<TEST_CASE>', async () => {
      // Код тестового примера

      // для утверждения определений переменных используй:
      // expect(<VARIABLE>).toBeDefined();

      // чтобы утвердить равенство, используй:
      // expect(<TEST_RESULT>).toEqual(<EXPECTED_VALUE>);
      // expect(<TEST_RESULT>).toStrictEqual(<EXPECTED_VALUE>);

      // для Promise используй асинхронное утверждение:
      // await expect(<ASYNC_METHOD>).rejects.toThrow(<ERROR_MESSAGE>);
      // await expect(<ASYNC_METHOD>).resolves.toEqual(<EXPECTED_VALUE>);
    });
});
});
```

Дополнительные рекомендации:

1. Тестирование крайних случаев: Выйди за рамки тестирования ожидаемых вариантов использования и убедись, что
   крайние случаи также протестированы для выявления потенциальных ошибок, которые могут быть незаметны при обычном
   использовании.
2. Избегай логики в тестах: Стремись к простоте в своих тестах, избегая такой логики, как циклы и регулярные
   выражения, поскольку они могут указывать на чрезмерную сложность теста.
3. Используй систему типов TypeScript: используйте статическую типизацию, чтобы выявлять потенциальные ошибки до их
   появления, что потенциально сокращает количество необходимых тестов.
4. Эффективно обрабатывай асинхронный код: Если твои тестовые примеры включают Promise и асинхронные операции,
   убедись, что они обрабатываются правильно.
5. Напиши полные тестовые примеры: избегай написания тестовых примеров в качестве простых примеров или каркасов
   кода. Тебе необходимо написать полный набор тестов. Они должны эффективно проверять тестируемую функциональность.
6. Твоя конечная цель - создать надежный, полный набор тестов для предоставленного кода на TypeScript.

Проверяй тесты и поправляй их по мере необходимости. Наша цель покрывать максимум функционала тестами.

Готовый файл с тестами распологай в директории:

```
tests
  composables
    useComposableName.test.ts
```
